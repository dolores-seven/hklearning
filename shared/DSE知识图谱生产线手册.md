# DSE 知识图谱生产线手册

> 从数学图谱实践中提炼的可复用方法。适用于 DSE 物理、化学及其他科目的知识图谱生产。

---

## 一、产品定义（先想透，再动手）

### 1.1 核心价值不是「知识点清单」，是「关系」

DSE 学生不缺知识点列表（课本上有）。他们缺的是：
- **哪些知识点会揉在一起考**（组合出题关系）
- **学这个知识点是在通往哪里**（前置/推导链）
- **一道母题的长什么样、变式有哪些**（母题体系）

图谱的差异化价值 = 关系边 + 母题，不是节点本身。

### 1.2 三个用户视角的「希望」

设计时始终从这三个时刻出发：
1. **考前 30 分钟**：拉远看全景，心里有底（全景地图感）
2. **刷题时**：一眼认出「这是哪几个知识点的组合」（题感训练）
3. **中四刚开始学时**：看见「这个知识点将来要和谁接上」（方向感）

### 1.3 内容边界铁律

- 知识范围 = 官方 C&A Guide 划定 + 历年真题实际考查
- 不超出考试范围、不引入大学内容、不凭经验臆造
- 教材章节仅用于对齐「按年级显示」，不作为知识范围的依据

## 二、数据模型（核心资产）

### 2.1 三层节点

```
范畴 (domain)
  └─ 课题 (topic)     ← 默认视图，30-40 个节点
       └─ 公式叶 (leaf) ← 下钻展开，200-300 个
```

每个叶子有三个知识类型（`knowledgeType`），用颜色区分：

| 类型 | 值 | 学习任务 | 颜色示例 |
|------|-----|---------|----------|
| 公式 | `formula` | 要背 + 会套 | 蓝色 |
| 公理·定理 | `theorem` | 要理解成立条件 + 会证 | 紫色 |
| 推论/衍生 | `corollary` | 要**认得出**，常是隐藏桥梁 | 琥珀色 |

### 2.2 四类关系边

| 类型 | 值 | 线型 | 含义 |
|------|-----|------|------|
| 前置 | `prereq` | 实线箭头 | 学 B 之前必须会 A |
| 推导 | `derives` | 虚线箭头 | B 从 A 推导出来 |
| 相关 | `related` | 点线 | 概念上有关联 |
| 组合出题 | `cotested` | 双线加粗 | 考试中经常一起出现 |

**组合出题边是最有价值的边**——它把图谱从「知识清单」变成「全景地图」。

### 2.3 母题（六要素）

每个母题必须包含六个要素，缺一不可：

```json
{
  "id": "mp-na-06-01",
  "titleZh": "判别式判断交点个数",
  "titleEn": "Discriminant for intersection points",
  "coreTopics": ["na-06"],
  "relatedTopics": ["ms-03", "ms-05"],
  "stem": "已知直线 y=mx+c 与圆 x²+y²=r²，求 m 的范围使直线与圆有两个交点",
  "stemEn": "Given a line y=mx+c and a circle x²+y²=r², find the range of m for two intersections",
  "questionType": "计算题",
  "solutionSkeleton": ["联立方程", "整理成标准二次方程", "判别式 Δ>0", "解 m 的不等式"],
  "variation": [
    "与圆相切（Δ=0）求 m 值",
    "与圆无交点（Δ<0）求 m 范围",
    "弦长计算（联立+韦达+弦长公式）"
  ],
  "appearances": [
    { "year": 2019, "paper": "P1", "question": "Q12b", "section": "B", "source": "confirmed" }
  ]
}
```

**⚠️ 字段名铁律（物理实战教训）**：
- 解法骨架用 **`solutionSkeleton`（数组）**，不是 `skeleton`（字符串）——渲染器对字符串调 `.join()` 会抛异常，整个详情面板崩溃
- 变式方向用 **`variation`（数组）**，不是 `variations`
- 题干用 **`stem` / `stemEn`**（中英双语，必填），不是可有可无
- 物理科目额外建议 `questionType`（計算題/解釋題/圖像題/實驗題）

**质量门槛**：没有变式方向（`variation`）的母题不进库——避免沦为真题的简单罗列。

### 2.4 每个叶子的 pitfall

每个公式叶子必须有 `pitfall` 字段，说明三件事：
- **何时用**（适用条件）
- **怎么用**（操作要点）
- **常见坑**（DSE 考试中的典型错误）

没有 pitfall 的叶子 = 没说透，学生看了公式也不知道怎么考。

### 2.5 考试频率标注

每个课题节点必须有：
- `examFrequency`：2012-2024 共 13 年中出现过多少年（0-13）
- `examSection`：主要出题位置（A1/A2/B/P2/Paper3）

> **注意**：`examFrequency`/`examSection` 需要可靠的 by-topic 数据源。物理科目没有免费数据源时，用 `weight`(high/mid/low) + `diff`(1-3) 承担重要性角色，不强造频率数字。

### 2.6 数据结构契约（Schema）——跨科目复用的头号教训

> 渲染器（`dse-math-map.html` / `dse-physics-map.html`）是一个**通用引擎**，但它与数据之间有一份**隐式契约**。新科目数据若不对齐这份契约，渲染器会以各种诡异方式崩溃（不画图、undefined、点节点无反应）。**做新科目时，数据建好后第一件事是跑契约校验，而不是等渲染器崩了再查。**

渲染器实际读取的全部字段：

**顶层**
```
meta           必填（对象）
nodes          必填（数组）
edges          必填（数组）
motherProblems 必填（数组）
domains        必填（数组，顶层！不能只放在 meta 里）
```

**domains[]**（渲染器用 `G.domains.find(d=>d.id===id)`）
```
id     必填，如 "PH-FM"
group  必填，用英文枚举：core / elective / sba（⚠️ 不要用中文字面量）
color  必填，如 "#3b82f6"（缺了 domColor() 返回 undefined）
code   {zh, en} 双语名称
```

**meta.knowledgeTypes**（⚠️ 必须是**对象** `{id: {zh,en,color}}`，不是数组！）
```
每个类型: zh, en, color
```

**meta.edgeTypes**（对象）
```
每个类型: zh, en, color, dash（"none" 或 "5 3"）
缺 color → render 里 def.color 报 TypeError，整图不渲染
```

**nodes[]**
```
id, level, domain, grades[S4/S5/S6]
name  {zh, en}
weight high/mid/low（缺 → 详情面板 undefined）
diff   1-3（缺 → 详情面板 NaN）
leaves[]
examFrequency / examSection（可选，有数据才标）
```

**leaves[]**
```
id, knowledgeType, name{zh,en}, formula, pitfall{zh,en}
dataSheet（物理特有，bool，是否在考试公式表）
pitfall 必须是 {zh,en} 对象，不是字符串（双语考试）
```

**edges[]**
```
from, to, type（prereq/derives/related/cotested）, evidence(可选)
```

**motherProblems[]**：见 2.3，字段名铁律

**其他渲染器硬编码点（复制后必须改）**：
- 初始节点位置角度映射：`{'NA':…,'MS':…,'DP':…,'M2':…}` → 必须换成新科目的 domain id
- 模块过滤 `isCore` 写死 `n.domain !== 'M2'` → 已改为按 `domGroup(n.domain)` 匹配
- 标题/副标题/版本号

### 2.7 母题进化：从「题型模板」到「小题库」（v2 核心经验）

> **用户反馈「母题太少，不够解题」后的核心洞察**：母题是题型模板，**不是题**。学生点开母题想练手时没有题可做——这才是「不够解题」的真相。解决方案：给每个母题挂**具体变式题**（variants），把母题升级成可刷的「小题库」。

**为什么要变式题而不是无限扩母题**：一道母题 + 3-5 道变式题 = 一整类题的覆盖，比「每课题堆 5 个母题模板」更直接解决刷题需求，且变式题可以带难度梯度（基础→进阶→挑战），支撑自学的「位置感」。

**variants 结构**（挂在母题上，数组）：

```json
{
  "id": "mp-xxx-01",
  "titleZh": "...",
  "stem": "母题题干",
  "variants": [
    {
      "difficulty": "basic",        // basic|intermediate|challenge|comprehensive|calc|concept|experiment
      "stemZh": "变式题1题干（具体可解的数字）",
      "stemEn": "Variant 1 stem (concrete solvable numbers)",
      "answerZh": "答案要点中文",
      "answerEn": "Answer points (English)",
      "years": ["2021"],            // 可选，对应真题年份
      "marks": [                    // 评分点（核心课题必填）
        { "content": "写 n(HCl)=cV=0.0025 mol", "pts": 1 },
        { "content": "由 1:1 摩爾比得 n(NaOH)", "pts": 1 }
      ],
      "lossZh": "常见失分中文",
      "lossEn": "Common mistake (English)"
    }
  ]
}
```

**掌握度三档映射**（渲染器内置，数据只需给 `difficulty`）：

| difficulty | 掌握档位 | 学生含义 | 颜色 |
|-----------|---------|---------|------|
| `basic` | 中四达标 | 中四结束应会 | 🟢 绿 |
| `intermediate` | 中五达标 | 中五结束应会 | 🟡 黄 |
| `challenge` / `comprehensive` | 冲5门槛 | 拉开差距，冲 5 的关键 | 🔴 红 |

**变式题质量门槛**（三科实战后定稿）：
- 每个母题**至少 3 道变式题**（基础/进阶/挑战各 1）
- 核心课题（高频 + 大分值）的变式题**必须补评分点**（2-4 个，每个标分值）+ 常见失分
- 变式题题干要有**真实可解的具体数字**（不是「若 a 增大…」这种抽象变化）
- 答案要点按**步骤拆开**（每题 2-4 步），不要一段话糊在一起

**为什么评分点（marks）是自学到 5 分的关键**：
> DSE 理科最残酷的真相是「算对了不一定拿分」——尤其解释题/实验题按评分点给分。学生自学最大的盲区是「写出了答案但不知道能不能得分」。把答案拆成「答到什么给几分 + 常见失分」，学生对着评分点**自评**，才知道自己写的答案值几分。

## 三、数据采集流程

### 3.1 官方框架（第一优先）

1. **下载官方 C&A Guide**：香港教育局官网，按学习单元（Learning Unit）梳理
2. **确认范畴划分**：每个 DSE 科目有自己的范畴结构
3. **确认年级分布**：哪些课题在中四、中五、中六

### 3.2 补习社交叉验证（第二优先）

搜索关键词模板：
```
DSE [科目] 卷一/卷二/卷三 出题频率 topic
DSE [科目] by topic 历年
DSE [科目] 操卷攻略 必考
DSE [科目] section B 常考组合
```

重点找的信息：
- 每个课题的出题频率和难度
- Section B 的跨课题组合规律
- "从未考过"的课题（避免浪费学生时间）

### 3.3 题号映射（第三优先）

搜索 "DSE [科目] by topic" + 年份范围，找按课题分类的真题索引。

**已知的困难**：
- DSE 没有免费的完整结构化题库（官方 OQB/DFS 是学校订阅制）
- 真题 PDF 通常是扫描版，OCR 数学公式准确率低
- 第三方网站（MathsKiller、Scribd）可能有付费墙或反爬

**务实策略**：先用补习社的定性频率数据标注，具体题号后续补充。

## 四、数据构建顺序

### Phase 1：骨架
1. 按 C&A Guide 建立课题节点（~30-40 个），标注年级、范畴
2. 画前置/推导关系边（学习路径）
3. 每个课题给 3-5 个核心公式叶子
4. 写 5-10 个示范母题（验证数据结构）
5. 搭建渲染器，能跑起来

### Phase 2：深化
1. **从"考好DSE"角度补叶子**：高频课题多补、低频课题精简
2. **pitfall 100% 覆盖**：每个叶子都有「何时用、怎么用、常见坑」
3. **母题库扩到 50+**：每课题至少 1 个，Section B 高频课题 2-3 个
4. **组合出题边扩到 60+**：用补习社交叉验证
5. **考试频率标注**：38/38 课题全覆盖

### Phase 3：校准
1. 搜索补习社题型分析帖
2. 交叉比对组合出题边是否遗漏
3. 核实频率数据

## 五、数据质量标准

### 5.1 必须通过的检查（自动化）

```
1. JS 语法可解析
2. 顶层结构完整（nodes/edges/motherProblems/meta）
3. 课题节点数正确
4. 叶子总数 >= 200
5. 边数 >= 100
6. 母题数 >= 50
7. 无悬空边（from/to 都指向存在的节点）
8. 无重复节点 ID
9. 课题全覆盖 examFrequency
10. 课题全覆盖母题（每个课题至少是 1 个母题的 coreTopic）
11. 叶子全覆盖 knowledgeType
12. 叶子全覆盖 pitfall（非空）
13. 母题无悬空引用（coreTopics/relatedTopics 指向存在的课题）
14. 母题全覆盖 variations（质量门槛）
```

### 5.2 叶子分布原则

- **不是追求数字**，是「说透说明白」
- 高频课题（年年考）：叶子 8-10 个
- 中频课题：叶子 6-7 个
- 低频课题（几乎不考）：叶子 3-5 个，只留「理解后续内容必需的」

### 5.3 数据独立原则

- 数据（`graph-data.js`）与渲染器（`dse-math-map.html`）完全解耦
- 数据用 `const DSE_MATH_GRAPH = {...}` + `module.exports` 双模式导出
- 数据是核心资产，网页只是它的一个视图
- 同一份数据可喂给 Obsidian、Anki、印刷版等

## 六、渲染器（可复用）

### 6.1 伪立体四机制

不是字面做 3D，用四个机制实现「结构感」：
1. **分层下钻**：默认只显示课题级，双击展开公式叶
2. **边类型开关**：四种边可独立开关，全景时只显示骨架线
3. **焦点辐射**：点击节点后，非关联节点淡出，只留中心+邻居
4. **题群引力**：组合出题频率作为弹簧强度，常考组合自然抱团

### 6.2 视觉编码

| 视觉通道 | 编码什么 |
|---------|----------|
| 颜色（色相） | 知识类型：公式 / 公理·定理 / 推论 |
| 形状 | 节点层级：范畴(大圆) / 课题(中圆) / 叶子(小圆) |
| 大小 | 考试权重 |
| 边线型 | 关系类型：实线/虚线/点线/双线 |
| 位置抱团 | 范畴分区 + 题群引力 |

### 6.3 新科目复用（⚠️ 物理实战证明：不是"复制改名就行"）

渲染器是通用引擎，但它**不是零配置的**。物理迁移时我们以为"改改名字就能用"，结果踩了一整轮坑（详见 7.4）。正确做法：

1. 复制 `dse-math-map.html` 为新科目 HTML
2. **对照 2.6 契约清单，逐个确认数据字段**：domains 在顶层且有 color/code、knowledgeTypes 是对象、edgeTypes 有 color/dash、节点有 weight/diff、叶子 pitfall 是 {zh,en}、母题用 solutionSkeleton/variation
3. **改渲染器里 3 处硬编码**：
   - 初始位置角度映射（`{'NA':…}` → 新科目的 domain id）
   - 标题 / 副标题 / 版本号
   - 模块过滤依赖的 `domGroup()`（确认 domain.group 用了英文枚举）
4. 替换 `graph-data.js` 为新科目数据
5. **先跑一次"渲染器视角"的 Node 模拟**（读数据 + 模拟渲染器读字段，打印所有 undefined）→ 再做浏览器实测
6. 数据层 14 项 + 渲染层 16 项测试全绿后才算完成

**核心认知**：契约不匹配时，渲染器崩溃的方式很多（不画图、undefined、TypeError、点节点无反应），**每一条都很难排查**。与其事后排查，不如事前用契约校验把问题拦在数据层。

### 6.4 掌握度自评系统（自学到 5 分的「位置感」）

> 用户视角洞察：自学最容易崩的不是「不会」，而是**「不知道自己会不会」**。做了半天题不知道自己在 5 分路径上的位置，就会盲目刷题或盲目放弃。掌握度自评系统就是解决这个「位置感」。

三科渲染器统一实现了三件套：

1. **难度 → 掌握档位标签**：每个变式题旁显示「中四达标 / 中五达标 / 冲5门槛」标签（颜色区分）
2. **「✔ 我会了」自评按钮**：点击后在 localStorage 存 `dse-mastery-<母题id>:v<序号>`，本地保存不丢失
3. **课题掌握度进度条**：详情面板母题区顶部显示三档计数 + 三色进度条（`中四达标 2/9 · 中五达标 1/9 · 冲5门槛 0/9`）

**⚠️ localStorage key 的格式必须全局一致**（这是实战踩过的真 bug，见 7.5）：进度条统计和自评按钮必须用**完全相同**的 key 生成规则，否则「按钮已掌握但进度条不动」。

## 七、踩坑记录（数学图谱实战教训）

### 7.1 工具层面

| 坑 | 教训 |
|-----|------|
| firecrawl MCP 的 ReadMcpResourceTool 会导致死循环 | 读本地文件只用内置 Read 工具或 Bash |
| JSON.stringify 后格式变了（引号、缩进） | 序列化后必须做语法校验 + 浏览器回归 |
| heredoc 里的中文引号/特殊字符导致脚本崩溃 | 写复杂 JS 脚本用 Write 工具写文件，不用 heredoc |
| Edit 工具对 LaTeX 反斜杠的匹配不稳定 | 大量数据修改用 Node 脚本 + JSON.parse/stringify |
| 全角括号（）和全角冒号：混入 JS 代码 | 代码中严禁中文标点 |

### 7.2 数据层面

| 坑 | 教训 |
|-----|------|
| 一开始追叶子数字（128→250）但忘了「说透说明白」 | 目标不是数字，是每个叶子都有 pitfall |
| 低频课题和高频课题叶子数一样多 | 按 examFrequency 分配叶子数量 |
| 课题名称误导（如「CAST三角」频率0但内容是高频的解三角形） | 课题名称要与 C&A Guide 对齐 |
| 母题 appearances 只有笼统的"LQ"/"MC" | 尽量补具体题号，哪怕只有部分 |

### 7.3 流程层面

| 坑 | 教训 |
|-----|------|
| 用户说「先出规划文档」我却直接开始写代码 | 每次新项目先出规划文档，确认后再动手 |
| 搜索外部数据时在一条路上撞墙很久 | 设定止损：一条路 3 次失败就换路线 |
| 真题 PDF 是扫描版才发现 OCR 不可行 | 先检查 PDF 是否有文字层，再决定路线 |

### 7.4 跨科目复用坑（物理实战，2026-08-20）

> 从数学迁到物理时，**手册 2.3 节自己就把母题字段名写错了**（`skeleton`/`variations`），加上渲染器有隐式契约，导致"照着手册做"做出来就是错的。以下是全部踩过的坑，化学图谱前必须逐条对照。

**A. 渲染器-数据契约不匹配（大部分问题的根源）**

| 坑 | 表现 | 教训 |
|-----|------|------|
| `domains` 只放在 `meta.domains`，渲染器读顶层 `G.domains` | 整图不渲染 | 契约清单第 1 条：domains 必须在顶层 |
| `knowledgeTypes` 是数组，渲染器当对象用 `G.meta.knowledgeTypes[kt]` | 图例 5 个 undefined | 必须是对象 `{id:{...}}` |
| domains 缺 `color`/`code` | 图例/详情 undefined | 见契约 |
| edgeTypes 缺 `color`/`dash` | **render 里 `def.dash` 抛 TypeError，整图崩溃** | 见契约 |
| 节点缺 `weight`/`diff` | 详情面板 undefined/NaN | 见契约 |
| 叶子 pitfall 是字符串不是 `{zh,en}` | 英文显示 undefined | 双语考试必须双语 pitfall |
| 初始位置角度映射用数学的 domain id（NA/MS/DP/M2） | 物理节点全部堆在原点 | 复制渲染器后必须改这段映射 |
| `isCore` 写死 `n.domain !== 'M2'` | 物理模块过滤失效 | 已改为按 `domain.group` 匹配，group 用英文枚举 |

**B. 数据层自身问题**

| 坑 | 教训 |
|-----|------|
| 母题 id 重复：44 个里有 4 条 id 撞车（复制粘贴没改 id），2 条完全重复、2 条内容不同但 id 相同 | 建数据后必须查重复 id；追加母题时用唯一 id |
| 母题字段命名不统一（`skeleton`/`variations` vs 标准 `solutionSkeleton`/`variation`） | 以契约清单为准，不用手册旧写法 |
| `skeleton` 是**字符串**，渲染器对它调 `.join()` | **抛异常 → 整个详情面板崩溃（点节点无反应）** | 必须是数组 |
| 母题缺 `stem`/`stemEn`（题干），只有骨架和变式 | 学生不知道"原题长什么样" | 题干是六要素核心，不能省 |

**C. 排查流程教训**

| 坑 | 教训 |
|-----|------|
| "看不到图"时在渲染器/数据里排查很久，实际是浏览器缓存了旧文件 | **先强制刷新（Ctrl+Shift+R）排除缓存，再排查代码** |
| 39KB 的 HTML 在上下文里整块重写/读取 | 大文件用 sed/grep 定位 + 精准 Edit，不用 Read 整块；触发 context 爆掉会中断 |
| 在浏览器里 console 查变量，但 IIFE 内部变量不在全局作用域 | 用 browser_eval 注入诊断，或把关键函数暴露到 window |
| 结构字段用中文字面量（"必修"/"選修"）导致硬编码比较失效 | 枚举值统一用英文 id（core/elective/sba） |

**D. 根治方法：契约校验脚本**

把 2.6 的契约清单写成 Node 校验函数（**已落盘：`contract-check.js`**），新科目数据建好后**先跑契约校验再碰渲染器**：

```bash
node contract-check.js physics/graph-data.js    # 校验某科目数据
node contract-check.js graph-data.js            # 校验数学基准
```

校验项：domains 顶层 + color/code + group 英文枚举、knowledgeTypes 是对象、edgeTypes 有 color/dash、节点有 weight/diff、叶子 pitfall 是 {zh,en}、母题有 stem/stemEn/solutionSkeleton/variation、无重复母题 id。**全部 ✓ 才允许进渲染器。**

> **数学 v0.2.0 的技术债（契约脚本实际检出的）**：数学数据本身未完全对齐契约——69 个叶子 pitfall 是纯中文字符串、16 个母题 solutionSkeleton 是字符串、domains 无 group（靠 isCore 硬编码兼容）。因数学已发布、渲染器 `nm()` 兼容字符串，暂不阻塞；**但化学图谱必须从一开始就全对齐**，不要模仿数学的旧写法。

### 7.5 数据结构级 bug（变式题 + 掌握度实战）

给母题挂变式题、加掌握度自评时踩了 3 个「看似小事、实际全崩」的 bug，全部在浏览器实测中暴露：

| 坑 | 表现 | 根因 | 教训 |
|----|------|------|------|
| **子实体没有唯一 id** | 掌握度去重只剩 1 道题；所有自评按钮共用同一个 localStorage key | variants 是数组下标定位，代码却用 `v.id`（undefined）做 Set 去重和 localStorage key | **数组型子实体必须有稳定的唯一标识**；渲染时用 `母题id + ':v' + 序号` 生成 |
| **key 生成规则不一致** | 「按钮已掌握，但进度条 0/9 不动」 | 进度条统计用 `母题id+':'+下标`（从 0 起），按钮用 `母题id+':v'+序号`（从 1 起） | **同一实体的 key 生成规则全局唯一**，进度统计和交互按钮必须用同一函数 |
| **去重用不存在的字段** | 所有变式题的 key 都是 `undefined`，只剩第一个进入统计 | `vSeen.has(v.id)` 里 `v.id` 不存在，全为 undefined | Set 去重前先确认 key 字段真实存在 |

**如何避免（下次直接做）**：
1. 数据里的数组型子实体（variants/marks），**在设计结构时就规划好唯一 key 字段**
2. 渲染器里抽一个公共函数 `vKey(m, i)`，所有用到 key 的地方（去重/进度/自评按钮/localStorage）都调它
3. 三科渲染器结构有差异（数学是箭头模板 `m => \`...\``，物理化学是函数体 `m => {…}`），批量替换脚本对部分文件会失配——**同步后必须逐个文件语法检查 + 浏览器实测**
